1.1 System Design কী?
System Design হলো এমন একটি process যেখানে একটি software system কীভাবে কাজ করবে, কীভাবে scale করবে, কীভাবে secure থাকবে এবং future growth handle করবে — সেই architecture ও infrastructure পরিকল্পনা করা হয়।
সহজ ভাষায়:
“একটা software শুধু code না, পুরো system কীভাবে efficiently চলবে সেটাই System Design।”

ধরুন আপনি একটি ছোট ERP software তৈরি করলেন।
প্রথমে:
১০ জন user
একটি server
একটি database
সবকিছু ভালো চলছিল।
কিন্তু ২ বছর পর:
৫০,০০০ user
হাজার হাজার transaction
Mobile app
API integration
Multiple branch
Real-time reporting
এখন system slow হতে শুরু করল।
এখান থেকেই শুরু হয় “System Design” এর আসল প্রয়োজন।

1.2 কেন System Design গুরুত্বপূর্ণ?
অনেক developer মনে করে:
“ভালো code লিখলেই system ভালো হবে।”
কিন্তু বাস্তবে:
ভালো code ≠ scalable system
ভালো database ≠ high availability
ভালো API ≠ production stability
একটা system এর success নির্ভর করে:
architecture
scalability
infrastructure
database design

এর উপর।

Security

RBAC
HTTPS

Maintainability
Future এ system modify করা সহজ হবে।

2.10 Basic Capacity Estimation
ধরুন:
একটি application এ:
১ লাখ user
Daily active user = ২০%
প্রতি user দিনে ৫০ request
তাহলে:
Daily Request:
100000 \times 0.2 \times 50 = 1000000
Daily request = 1 million

Requests Per Second (RPS)
ধরি peak traffic daily traffic এর ১০% এক ঘণ্টায় আসে।
তাহলে:
RPS = \frac{100000}{3600} \approx 28
Approx 28 request/sec
এটাই system design এর ভিত্তি।

2.11 Storage Estimation
ধরি:
প্রতি transaction = 5 KB
Daily transaction = 2 million
তাহলে:
2000000 \times 5KB = 10GB/day
১ বছরে:
10GB \times 365 = 3650GB
≈ 3.6 TB/year
এখন architect বুঝতে পারবে:
partition লাগবে?
archive লাগবে?
sharding লাগবে?
